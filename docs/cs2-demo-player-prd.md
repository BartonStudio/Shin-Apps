## 2. 完整生命周期（从打开到关闭）

> 按用户操作的时间顺序，覆盖「正常路径」与「异常路径」。
> 每一条步骤对应后文「功能需求明细」里的一个功能点（F0~F9）。

### 2.1 启动应用

- 用户双击打开应用。
- 进入初始化加载页面（启动画面）。

### 2.2 初始化加载（启动画面）

- 应用启动后先进入初始化加载页面，LOGO 下方显示当前正在执行的工作描述。
- 后台依次执行启动自检项（如文件完整性校验等，具体清单待定），每项进行时同步更新 LOGO 下方的描述文字。
- 加载过程中播放背景音乐（兼具品牌特色与音频水印作用，见 F0）。
- 全部自检通过后，自动进入主界面（空状态）。

异常路径：

- 某项自检失败（如文件完整性校验不通过）→ 在加载页给出提示，不进入主界面（具体处置待定）。

### 2.3 主界面（空状态）

主界面显示：

- 「打开 Demo」按钮。

### 2.4 打开 Demo（两种入口，均可）

用户可通过以下任一方式打开一个 `.dem` 文件：

- 点击主界面的拖放区（dropzone），弹出文件选择框（文件过滤器只显示 `.dem` 文件，强制限定 `.dem` 后缀），选择 `.dem` 文件。
- 将 `.dem` 文件从外部拖拽到拖放区（dropzone）内；拖放区以外的窗口区域不响应拖拽；非 `.dem` 后缀的文件即使拖入拖放区也不响应。

异常路径（按顺序判定）：

- 先判定文件扩展名是否为 `.dem`：不是 → 拒绝并提示。
- 再尝试解析判定能否打开：解析失败 / 文件损坏 → 弹错误提示「无法打开该文件」，停留在主界面。

### 2.5 加载解析（边解析边播放，优先）

- 打开文件后立即开始解析，**解析出前几秒内容即可开始播放**，无需等待整个文件解析完成。
- 播放过程中持续在后台解析后续内容。
- 已解析进度需在 UI 中可见（时间轴/进度条上区分「已解析」与「未解析」区域）。
- 若实现上边解析边播放有困难，**降级方案**为：解析完再进入观看（解析期间显示进度条）。

异常路径：

- 解析失败 → 弹错误提示，返回主界面。
- 解析到中途失败 → 提示已解析部分仍可观看，或返回主界面（以可实现为准）。

### 2.6 观看主界面

进入观看界面后，界面分为以下区域：

- **中间**：3D 比赛画面。
- **顶部**：回合比分与回合信息（与 CS2 原生 demo 播放器一致：显示 CT 与 T 双方队徽、当前比分、当前回合号及回合剩余时间）。
- **右上角**：击杀播报（Kill Feed，实时展示击杀/死亡信息）。
- **两侧**：玩家比分板（可通过底部按钮隐藏）。
- **底部**：控制栏（时间轴进度条 + 播放/暂停 + 倍速 + 上一回合/下一回合 + 显示/隐藏比分板按钮；进度条可视化「已解析进度」）。

### 2.7 播放控制

- 播放 / 暂停（底部控制栏）。
- 拖动底部时间轴进度条，跳转到指定时刻；目标位置未解析时，跳转不生效并恢复到当前位置。
- 倍速播放（档位：0.5x / 1x / 2x / 4x）。
- 上一回合 / 下一回合跳转。

### 2.8 点击玩家切视角

- 点击比分板上的某个玩家名字，切换相机到该玩家的视角。
- 该玩家存活 → 相机切到其位置与朝向。
- 该玩家已阵亡 → 给出提示。
- 正在观测的玩家阵亡 → 自动切换到顺序中的下一个存活玩家：先同阵营，再敌方阵营；场上无存活玩家则保持不动。

### 2.9 裁剪 Demo（导出片段）

- 用户在观看界面点击「裁剪」，打开裁剪 UI。
- 在裁剪 UI 中输入起始/终止时间戳，或拖动进度条手柄设置起始/终止时刻。
- 选择保存模式（全量保存 / 从起始时刻增量保存，默认后者）。
- 点击「裁剪并导出」，弹出文件保存对话框，导出裁剪后的 `.dem` 片段。
- 导出完成后回到观看界面，原 demo 不受影响。

异常路径：

- 起始时刻 ≥ 终止时刻 → 提示并禁止导出。
- 区间超出已解析范围 → 提示等待解析或调整区间。

### 2.10 退出观看

- 用户关闭观看界面或点击「退出」，回到主界面。

### 2.11 关闭应用

- 用户关闭窗口，应用退出。

## 3. 功能需求明细

> 每个功能按「入口 → 交互 → 规则 → 异常」描述。

### F0 应用初始化加载（启动画面 + 音频水印）

- **入口**：应用启动（双击打开）。
- **交互**：
  - 显示启动画面：LOGO + LOGO 下方动态工作描述文字；
  - 每项启动自检进行时，LOGO 下方文字更新为该项描述（如「正在校验文件完整性…」）；
  - 加载过程中播放背景音乐；
  - 全部自检通过后自动进入主界面（空状态）。
- **规则**：
  - 启动自检项至少包含文件完整性校验（完整清单待定）；
  - 自检项串行/并行执行均可，但 UI 描述需真实反映当前进行项；
  - 背景音乐承担两重作用：
    - **品牌特色**：作为启动体验的一部分；
    - **音频水印（防伪 / 版本追踪）**：不同发布版本内嵌不同的音频水印（或不同旋律指纹），并记录「版本 → 水印」映射；若他人基于某个版本逆向或二次分发，可通过提取其分发物中的音频水印，比对映射表判定其逆向基于哪个版本。
  - 音频水印应满足：听感可接受、可抗常见转码 / 重编码、可从分发物中被稳定提取与比对。
- **异常**：
  - 某项自检失败（如文件完整性校验不通过）→ 在加载页给出提示并停止进入主界面（具体处置待定）。

### F1 打开 Demo

- **入口**：主界面拖放区（dropzone）点击；或外部拖拽 `.dem` 文件到拖放区内。
- **交互**：点击拖放区弹出文件选择框，文件过滤器只显示 `.dem` 文件（强制限定 `.dem` 后缀）。
- **规则**：
  - 两种入口最终都指向「加载解析」流程；
  - 拖拽仅限拖放区（dropzone）响应，拖放到窗口其他区域无效；
  - 非 `.dem` 后缀的文件即使拖入拖放区也不响应（静默忽略，不提示、不进入解析）。
- **异常**（按顺序判定）：
  - 文件扩展名不是 `.dem`（经文件选择框选择的场景）→ 拒绝并提示；
  - 扩展名正确但解析失败 / 文件损坏 → 提示「无法打开该文件」，停留在主界面。

### F2 加载解析

- **入口**：用户打开 demo 后自动触发。
- **交互**：边解析边播放（优先）；降级为进度条 + 解析完进入。
- **规则**：
  - 解析到前几秒即可开始播放；
  - 播放过程中后台继续解析；
  - 已解析进度在 UI 中可见（时间轴/进度条区分已解析与未解析区域）；
  - 进度条降级方案下，解析完成后自动进入观看界面。
- **异常**：解析失败 → 错误提示，返回主界面。

### F3 3D 比赛画面

- **入口**：观看主界面中间区域。
- **交互**：实时渲染当前 tick 的比赛场景（地图、玩家、武器、投掷物等）。
- **规则**：随播放/暂停/跳转实时刷新；手雷等短命实体在其存活区间显示，之后消失。
- **异常**：渲染失败（如资源缺失）→ 尽量降级显示，不崩溃。

### F4 播放控制

- **入口**：底部控制栏。
- **交互**：
  - 播放 / 暂停按钮切换；
  - 拖动时间轴进度条跳转；
  - 倍速菜单（点击「倍速」按钮展开，选择档位：0.5x / 1x / 2x / 4x）；
  - 上一回合 / 下一回合跳转。
- **规则**：
  - 播放时画面按 64 tick/秒推进；
  - 跳转到指定 tick 后，画面与比分板同步刷新到该时刻；
  - 倍速影响播放速度，不影响已解析数据；
  - 倍速菜单与 POV 菜单互斥展开：一次只能展开一个菜单，展开其中一个时另一个自动收起（实际使用中两者不会同时展开）。
  - 上一回合 / 下一回合跳转到对应回合的开始；
  - 进度条上「已解析」与「未解析」区域可视化区分。
- **异常**：跳转到尚未解析的区域 → 跳转不生效，进度条恢复到当前位置。

### F5 点击玩家切视角

- **入口**：点击比分板上的玩家名字；或通过 POV 菜单选择观察目标。
- **交互**：相机切换到该玩家视角。
- **规则**：
  - 玩家存活 → 相机切到其当前位置与朝向；
  - 玩家已阵亡 → 给出提示；
  - 正在观测的玩家阵亡 → 自动切换到顺序中的下一个存活玩家（按比分板顺序：先同阵营，再敌方阵营）；场上无存活玩家则保持不动。
- **异常**：玩家在当前 tick 不存在（尚未出生或已离场）→ 给出提示。

### F6 比分板与回合信息

- **入口**：观看主界面两侧区域（比分板）；顶部区域（回合信息）；底部控制栏（显示/隐藏按钮）。
- **交互**：展示当前比赛的各玩家信息与回合信息；点击底部按钮切换比分板显示/隐藏。
- **规则**：
  - 每名玩家展示：名字、队伍、经济、K（击杀）、D（死亡）、A（助攻）、ADR，以及是否存活；
  - 顶部回合信息与 CS2 原生 demo 播放器一致：CT 与 T 双方队徽、当前比分、当前回合号及回合剩余时间；
  - 比分板随播放/跳转同步刷新到当前 tick 的状态；
  - 玩家名字可点击（触发 F5 切视角）；
  - 底部「显示/隐藏比分板」按钮：切换两侧比分板的显隐，隐藏后仅保留 3D 画面与必要控制，提供更纯净的观看体验。
- **异常**：数据缺失（如某些玩家无统计）→ 显示为空或默认值，不崩溃。

### F7 击杀播报

- **入口**：观看主界面右上角区域。
- **交互**：实时展示击杀/死亡信息。
- **规则**：
  - 展示击杀者、被击杀者与武器（格式与 CS2 原生一致，如「X ▸ AK-47 ▸ Y」）；
  - 爆头、助攻等信息随播放同步展示；
  - 随播放/跳转同步刷新到当前 tick。
- **异常**：数据缺失 → 不显示该条播报，不崩溃。

### F8 投掷物与 C4

- **入口**：观看主界面中间区域（3D 画面）。
- **交互**：显示投掷物与 C4 实体及其轨迹。
- **规则**：
  - 投掷物（手雷、闪光弹、烟雾弹、燃烧弹/莫洛托夫、诱饵弹）与 C4 炸弹均作为实体被解析和记录，在其存活区间显示；
  - 投掷物显示飞行轨迹（从抛出点到落点/爆炸点）；
  - 烟雾弹显示烟雾覆盖范围，燃烧弹/莫洛托夫显示燃烧区域；
  - C4 显示携带、安放位置、倒计时与爆炸；
  - 随播放/跳转同步刷新到当前 tick。
- **异常**：数据缺失 → 不显示，不崩溃。

### F9 Demo 裁剪（导出片段）

> 官方/第三方平台的 `.dem` 多为增量式，本应用解析后可还原完整现场，裁剪在此基础上完成。技术可行性详见 `docs/cs2-demo-trim-design.md`。

- **入口**：观看主界面的「裁剪」按钮（仅在 demo 加载解析成功后可用）。
- **交互**：
  - 点击「裁剪」打开裁剪 UI（弹窗/面板）；
  - 裁剪 UI 提供两种设置方式，二者双向联动：
    - 时间戳输入：输入起始/终止时间戳（如 `mm:ss` 或 `mm:ss.mmm`）；
    - 进度条手柄：拖动起始/终止两个手柄设置区间；
  - UI 实时显示所选区间及区间时长；
  - 选择保存模式（见「规则」），默认「从起始时刻增量保存」；
  - 点击「裁剪并导出」→ 弹出系统文件保存对话框（文件资源管理器），选择保存位置与文件名后导出。
- **规则**：
  - 裁剪区间为 `[起始, 终止)`，起始 < 终止，且必须落在已解析范围内；
  - 时间戳按 64 tick/秒 换算为 tick（tick = 秒 × 64）；
  - 时间戳输入与进度条手柄双向联动，任一侧改动实时同步另一侧；
  - 导出文件名默认带原文件名与时间区间（如 `xxx_1830-1853.dem`）；
  - 保存模式二选一：
    - **全量保存**：在起始时刻重建完整状态快照（stringtable 快照 + 全实体 full update），导出为自包含、可被任意播放器独立播放的 `.dem`（文件较大）；
    - **从起始时刻增量保存（默认）**：仅保留区间内的增量帧、不重建完整快照（文件较小，独立可播性见开放问题）；
  - 裁剪不修改原 `.dem` 文件。
- **异常**：
  - 起始 ≥ 终止 → 提示并禁止导出；
  - 区间超出已解析范围 → 提示等待解析或调整区间；
  - 全量保存重建快照失败（如缺少实体状态）→ 提示导出失败，可尝试增量保存。

### F10 电影模式

- **入口**：观看主界面（入口控件待定，如按钮/菜单项）。
- **交互**：
  - 进入电影模式后，观看界面的 UI 形态发生变化（隐藏/简化常规 HUD 元素，呈现更沉浸的观看形态；具体变化细节待补充）；
  - 进入电影模式后，右上角的窗口按钮（最小化 / 最大化 / 关闭）隐藏；双击标题栏不再触发最大化/还原；
  - 退出电影模式后恢复常规观看界面（窗口按钮恢复显示，双击标题栏恢复最大化/还原）。
- **规则**：待补充（如相机行为、与 POV 切视角 F5 的关系、电影模式下的播放控制方式等）。
- **异常**：待补充。

### F11 热键系统

- **入口**：应用全局（设置项 + 运行时）。
- **交互**：
  - 应用窗口可监听热键，触发对应功能；
  - 提供**启动前设置**：可在启动前配置默认键位（具体设置形态待补充）；
  - 支持**运行时动态换绑**：不改配置文件、不重启应用即可重新绑定热键；
  - 支持热键的**启用 / 禁用**：可单独开启或关闭某个热键。
- **规则**：待补充（热键清单、各热键对应功能、冲突处理策略等）。
- **异常**：待补充（如热键被其他程序占用时的处理）。

## 4. 非功能需求

### 4.1 平台与窗口壳层

- Windows 桌面应用。
- 技术栈：C++ 内核 + WebView2 / 原生 UI。
- **窗口形态**：
  - 采用自定义无边框窗口，标题栏由应用自绘，右上角提供最小化、最大化/还原、关闭三个窗口按钮；
  - 窗口控制（最小化 / 最大化 / 还原 / 关闭）由前端发起，经桥接消息交由 native 层执行；
  - **不支持拖拽窗口边缘调整窗口大小**，仅支持「窗口化」与「最大化（铺满工作区、不遮挡任务栏）」两种状态，通过标题栏按钮或双击标题栏切换。
- **DPI 与视口锚定**：
  - 界面按 1280×720 逻辑像素（设计尺寸）布局；
  - 任意 DPI 下，窗口还原态的 CSS 视口恰好为 1280×720（外框物理尺寸 = 设计尺寸 × DPI 缩放）；
  - DPI 变化时窗口尺寸/位置需兜底收敛，不得超出屏幕工作区。
- **关闭流程**：
  - 用户点击关闭按钮时，native 层先向前端发出关闭请求通知（`WindowCloseRequested`），再执行关闭。
  - 退出方式保留两种方案：
    - **直接关闭**：点击关闭按钮立即退出应用；
    - **询问确认**：弹出「是否保存 / 确认退出」询问后再退出；
  - 具体采用哪种方案未定（见开放问题），但关闭拦截能力（先通知前端、可中止关闭）必须具备。
- **浏览器原生行为禁用**：禁用 WebView2 内浏览器原生的任何快捷键组合（如 Ctrl+F、Ctrl+P、Ctrl+T、F5 等），键盘行为由应用自行接管（含 F11 热键系统）。

### 4.2 交互与动效

- **交互动效参数**（体验定稿，需与实现保持一致）：
  - 流动边框动画：30s / 圈，光点段占周长 16%；
  - 屏间切换：交叉淡入淡出，进入 0.4s / 离出 0.16s；两屏 LOGO 按视觉宽度比例做等比缩放回弹过渡；
  - 观看界面 HUD 元素错峰飞入（逐项递增延迟）；
  - 背景色切换（启动画面 ↔ 主界面）渐变过渡。
- **全局禁用文本选中**：整个 UI 禁止文本选择/拖蓝（`user-select: none`），播放器类应用防止误选中界面文字。
- **版本号角标**：主界面右下角常驻显示当前版本号（如 `V0.1.0`）。
- **不做响应式布局**：界面按固定 1280×720 视口设计，各区域采用绝对定位像素布局；仅窗口最大化时内容铺满全屏，不做多断点自适应。

### 4.3 性能

- 播放流畅度：正常播放（64 tick/秒）时画面流畅不卡顿。
- 加载体验：边解析边播放模式下，从打开到可播放的时间尽可能短；降级方案下进度条真实反映解析进度。
- 拖进度条跳转：已解析区域的跳转应即时响应。

### 4.4 稳定性

- 异常文件、损坏 demo 不得导致崩溃，应给出友好提示。
- 关闭观看界面、退出应用时，资源正常释放。

### 4.5 软件安全

> 本章为占位，内容待补充。

- **定义**：凡不是按照预期方式启动 / 操作本应用的用法，均视为不安全行为，需尽量避免。
- 已识别的不安全场景（初始记录）：
  - 绕过 WebView 外壳，直接加载应用的静态资源（前端产物）使用；
  - 基于本框架（壳层 / 内核）做二次开发、拆分复用或再分发。
- **防护措施与具体策略**：待补充（如资源加密 / 完整性校验 / 外壳绑定校验等，后续细化）。

## 5. 开放问题

1. 点击「已阵亡」玩家时，切视角失败的具体提示方式（弹窗 / 比分板标记 / 高亮）。
2. 「从起始时刻增量保存」导出的片段能否被第三方播放器独立播放？若不能独立播放，则不满足「分发给其他玩家」的主用途，需重新评估默认保存模式（是否默认改为「全量保存」），或明确增量模式的适用场景（仅本应用回放）。
3. 裁剪区间跨回合时是否需要额外处理（快照 / 回合边界），参考 `docs/cs2-demo-trim-design.md`。
4. 初始化自检的完整清单待定（除文件完整性校验外还包括哪些项），以及各项失败时的处置方式（重试 / 提示修复 / 阻止启动）。
5. 音频水印的具体实现方式待定：是「不同版本播放不同音乐作为版本指纹」，还是「在音乐中嵌入不可感知的水印信息」；以及提取 / 比对工具链（用于逆向分发的溯源判定）如何提供。
6. 电影模式（F10）细节待补充：进入后的具体 UI 变化清单、相机行为（自动运镜 / 自由观战）、与 POV 切视角（F5）的关系与切换方式、电影模式下的播放控制方式。
7. 退出应用采用「直接关闭」还是「询问保存 / 二次确认」方案待定（4.1 关闭流程已定义拦截能力，两种方案均需保留实现可能）。
8. 热键系统（F11）细节待定：热键清单、各热键对应功能、启动前设置的设置形态（配置文件 / 设置界面）、热键冲突与被占用时的处理策略。
